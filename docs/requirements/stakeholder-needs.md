# Stakeholder Needs (SN-###)

Owned by the **Stakeholder** hat (Owner, the homelab operator). Plain-language
needs + edge-case expectations. Engineering translations live in
`system-requirements.csv` (referenced by `SN-Refs`); do not restate them here.
Priority: **M**=Must · **S**=Should · **C**=Could.

This repo is a **config/infra deliverable** (compose, Caddy, autoinstall,
provisioning), scaffolded at the **minimum profile** with a **HIGH** decision
dial (secrets-adjacent infra — ratify often). The spine is kept deliberately
**high-level**: a handful of SN/SR rows about the stack, the image, auth, and
remote management — not deep LLR/TC rows per config file (proportionality
doctrine; the tracker binary's own requirements live in NagLight).

## Edge-case expectations

Delete-only rows that genuinely cannot apply; others are marked n/a explicitly.

| SN-ID | Lifecycle | Scenario | Expected behavior |
|---|---|---|---|
| SN-001 | Provision | Autoinstall media missing the payload | `late-commands` copy is best-effort (`|| true`); the box still installs and the operator can drop the stack manually. |
| SN-007 | Provision | First-run docs / discoverability | Stack README + root README + `.env.example` comments name every knob and the Owner manual step; a quick-reference table lists the minimum keys. |
| SN-008 | Startup | `.env` still has `REPLACE_WITH` placeholders | First-boot warns loudly, brings the stack up anyway, and tells the operator to edit `.env` and re-run the idempotent first-boot script. |
| SN-001 | Startup→Runtime | Unattended run must never block on a prompt | Autoinstall is fully non-interactive; provisioning + first-boot are idempotent and non-interactive; failures exit nonzero and land in the journal. |
| SN-001 | Runtime | Power loss / crash mid-operation | `restart: unless-stopped` + the idempotent first-boot unit reconverge on the next boot; Docker volumes persist state. |
| SN-003 | Runtime | A non-allow-listed Google account tries to sign in | oauth2-proxy rejects it; the tracker never receives the request. |
| SN-003 | Runtime | The tracker port is probed directly (bypass attempt) | The port is `expose`-only (bridge), never host-published; trusted headers are only honoured from oauth2-proxy. |
| SN-005 | Runtime | The Owner needs to fix a broken box remotely | SSH + Cockpit for live ops; the reimage ladder memo (`REMOTE_MANAGEMENT.md`) covers the worst case — nothing destructive is enabled without the Owner's checkbox. |
| SN-002 | Runtime | The hub box goes down | Burn-in checklist requires picking a secondary/failover DNS so an outage degrades gracefully rather than killing LAN resolution. |
| SN-005 | Runtime | Reimage-over-LAN is inherently destructive on an ambiguous target | HIGH-RISK: the memo presents options with checkboxes; no GRUB-reinstall/PXE/wipe path is implemented until the Owner ratifies one. |
| SN-009 | Runtime | A tier-2 service misbehaves (OOM, crash-loop, disk pressure) | The core is insulated: tier-2 is off by default; docs cap the photo stacks at one and flag `mem_limit` for heavy services; disable = remove the profile from `COMPOSE_PROFILES` and re-run `docker compose up -d --remove-orphans`. |
| SN-010 | Runtime | The run dies mid-copy while a container is quiesced (stopped) | The EXIT trap restarts every still-stopped container on ANY exit path — a failed backup must never leave a service down; a restart failure is a LOUD warning naming the manual command. |
| SN-010 | Runtime | docker CLI missing / a named volume doesn't exist | The set fails loudly (never-silent-green: `ok=false` + nonzero exit); other config forms (cifs-only) never invoke docker at all. |
| SN-012 | Runtime | Box reboots while the opt-in UI + IceDrive are in use | The core self-heals per SN-001; the GUI session does NOT auto-resume — sync stays down until the Owner opens one RDP session (the app autostarts inside it). Documented as the accepted, minimized deviation; the backup performs no offsite step (Owner 2026-07-29), so a stalled cloud sync is NOT visible to the backup report — a dedicated check is an open decision (see `docs/status.md`). |
| SN-012 | Provision | Reimage of a box that had the opt-in enabled | GUI-configured state (IceDrive login, sync pairs) is NOT reproducible from the repo — the opt-in README carries the re-setup checklist; the core reimage/recovery flow is unchanged. |
| SN-012 | Runtime | RDP port probed / exposure risk | xrdp is LAN-only like Cockpit: never proxied through Caddy, never port-forwarded at the router; the WireGuard path (D5) is the only sanctioned remote route. |
| SN-013 | Runtime | A device that is NOT the panel reaches the kiosk site (LAN, guest Wi-Fi, IoT, or the WAN — the name resolves publicly via the DDNS wildcard) | `respond 403` at the edge before any handler runs. Three independent layers: the `/32` source match, the LAN-bound publish of an alternate port, and the router forwarding only :80/:443. The off-LAN leg is a documented hardware test, not an assumption. |
| SN-013 | Runtime | A client forges `X-Forwarded-User`/`-Email` at the kiosk site | The injected identity wins: the site sets the panel's identity, which REPLACES any client-supplied value. Asserted with a forged header in the V1 sim (never inferred from Caddy's defaults), because NagLight's trusted-header mode has no header HMAC in v1. |
| SN-013 | Runtime | The panel's DHCP lease moves (a random MAC, a reservation lost) | The site 403s the panel — it fails CLOSED, and the panel shows an error rather than the wrong person's data. MAC randomization is pinned off and the reservation is keyed to the hardware MAC precisely so this stays a theoretical case. |
| SN-013 | Runtime | Mains blip during the nightly sleep window (no battery = no UPS, D-W5/quirk 4b) | The panel may simply stay OFF: this BIOS has no AC-recovery setting and a smart plug cannot press a power button. Accepted, with two consequences designed for — mount with the power button reachable, and the panel-down alert (an Uptime-Kuma push monitor, server-side) is REQUIRED rather than optional. |
| SN-013 | Runtime | Resume from S3 fails (the classic 2016-firmware failure) | `SLEEP_MODE=backlight` is the graceful degradation, sharing the same schedule so switching is a one-line change. If the RTC alarm cannot even be ARMED, the panel refuses to suspend at all and falls back to backlight-off for that window — a reachable panel beats a dark one. |
| SN-013 | Runtime | The panel's shell app crashes | The kiosk session restarts it; if the artifact is missing entirely the screen says so in words. A dead panel must be a visible event, never a black rectangle. |
| SN-013 | Provision | A quirk fix needs a value only the running hardware can supply (input device names) | The template ships with the knob EMPTY and first boot says loudly that the fix was not applied. Guessing a device name risks disabling the touchscreen — the panel's only input — so `WALL-BURN-IN.md` carries the procedure instead. |
| SN-013 | Provision | The panel is broken, lost, or its GUI state is unrecoverable | Reimage it. Nothing on the panel is precious (thin client, disposable cache), so it is explicitly reimage-not-repair — unlike the hub box. The one-time Pandora sign-in is the known cost of a reimage. |
| SN-014 | Provision | A reimage carries old separate drive-health units or tracker definitions | Provisioning refuses mixed old/new presentation wiring or reports it visibly; it never emits both the combined item and legacy drive rows. |
| SN-014 | Startup | The health monitor starts before Samba or the library mount is ready | The combined item is red until both checks pass; startup ordering cannot manufacture a backup success. |
| SN-014 | Runtime | The share fails and recovers between FileBackup passes | Failure sets the immediate red override; recovery clears only that override and restores the age band from the unchanged last verified success. |
